# План развития DriverCheck

## Цель

Сделать небольшой, понятный и безопасный инструмент диагностики драйверов Windows, который:

- показывает состояние устройств и установленных драйверов;
- честно отделяет ошибку устройства от неполных данных;
- не изменяет систему;
- постепенно приближается к проверке доступных обновлений, не превращаясь в установщик.

Проект учебный: каждое изменение должно быть понятным, обратимым и проверяемым.

## Принципы

1. **Только чтение.** Никаких установок, удалений и замен драйверов.
2. **Честные формулировки.** «Устарел» — только при наличии проверяемого источника и сравнения версий.
3. **Один шаг за раз.** План → правка → проверка → результат пользователя → следующий шаг.
4. **Обратимость.** Перед изменением — резервная копия с меткой времени и проверкой SHA-256.
5. **Сохранение кодировки.** UTF-8 с BOM, совместимость с Windows PowerShell 5.1.
6. **Разделение слоёв.** `scan` отвечает за состояние устройства, будущая проверка обновлений — за доступность новой версии.
7. **Без чужих данных.** Никаких серверов и файлов Driver Booster, никакого копирования закрытого кода.

## Этапы

### Этап 1 — инвентарь и `list` (готово)

- Добавлена общая функция `Get-DcInventory`.
- `list` переведён на общую модель.
- Удалена команда `outdated`: дата или версия без источника не доказывают устаревание.
- Сохранены UTF-8 BOM и совместимость с PowerShell 5.1.

### Этап 2 — единая модель и статусы (готово)

- `scan` и `info` переведены на `Get-DcInventory`.
- Добавлено `ProblemDescription`.
- Введены правила статусов: `0` → `OK`, `45` → `NotPresent`, `22` → `Disabled`, другой код → `Problem`, отсутствие кода → `Unknown`.
- `Presence` хранится отдельно от `Status`.
- `Partial` и `Conflict` показываются отдельно от ошибок устройства.
- В таблицу `Partial` добавлены `Presence` и `Status`, счётчики разделены на `Present`/`NotPresent`.

### Этап 3 — ошибки и коды возврата (готово)

- `0` — успех; для `scan` — проблем нет.
- `1` — `scan` нашёл устройства, требующие внимания.
- `2` — неизвестная команда.
- `3` — не удалось получить данные об устройствах.
- `Get-PnpDevice` и `Win32_PnPSignedDriver` обёрнуты в отдельные `try/catch` с понятным сообщением.
- В `help` добавлен раздел «Коды возврата».
- Версия поднята до `0.7.0`.

### Этап 4 — проверка обновлений (проект готов)

Проект описан в [`docs/UPDATE-CHECK.md`](docs/UPDATE-CHECK.md).

Ключевой вывод: Windows Update Agent (`IWindowsDriverUpdate`) даёт Hardware ID, класс, производителя, модель, поставщика и дату версии, но **не даёт структурированную версию кандидата**. Поэтому первая версия проверки может честно говорить только:

- `Offered` — Windows Update предлагает обновление, совпавшее по Hardware ID;
- `NotOffered` — источник ничего не предложил (это не значит «актуально»);
- `Unknown` — данных недостаточно;
- `NotApplicable` — устройство не подключено.

Слова «устарел» в выводе не будет, пока не появится проверяемый источник версии кандидата.

Следующий шаг — read-only проба WUA. Она делает сетевой запрос к Windows Update и выполняется только после явного согласия пользователя.

## Ближайшие задачи

1. Проверить README, PLAN и проект проверки обновлений.
2. Согласовать и выполнить read-only пробу WUA (сеть, без скачивания и установки).
3. По результатам пробы решить, реализовывать ли `check-updates` в режиме `Offered`/`NotOffered`/`Unknown`.
4. Выровнять счётчики в `info`: `$present` считается по `Presence`, а `$notPresent` — по `Status`; сейчас числа совпадают, но логика различается.
5. Разделить причины `Partial`: «записи нет» и «запись есть, но поля пустые».
6. Уточнить формулировку «Неполные данные о драйвере» → «Нет полной записи о драйвере».

## Бэклог

- Автоматические тесты (Pester или собственный harness) для статусов, `Partial`/`Conflict` и кодов возврата.
- Проверка поведения на другой машине и другой версии Windows.
- Оформление вывода `list`/`scan` в JSON для скриптов (только после стабилизации модели).
- Документирование формата `DataQuality` и правил сравнения версий.
- Ревизия глобальной переменной `$script:DcProblemCount`: при росте скрипта лучше возвращать объект результата.

## Не делаем

- не устанавливаем, не удаляем и не заменяем драйверы;
- не меняем реестр, Driver Store и настройки системы;
- не ходим в сеть из `scan`, `list`, `info`, `help`;
- не обращаемся к серверам и файлам Driver Booster;
- не обходим лицензии и защиту;
- не копируем закрытый код;
- не объявляем драйвер устаревшим без проверяемого источника.

## Как проверяем изменения

1. Бэкап `drivercheck.ps1` с меткой времени.
2. SHA-256 копии совпадает с исходником.
3. Правка только в нужных местах, без полной перезаписи.
4. Проверка BOM (`ef bb bf`) и синтаксиса (`PARSE_OK`).
5. Дифф: только ожидаемые строки.
6. Команды проверки запускает пользователь; результат сверяется с ожидаемым.
7. Для сбоев источников — отдельные временные копии, рабочий файл не ломается.
