# DriverCheck

**Read-only диагностика драйверов Windows в PowerShell.**

![PowerShell](https://img.shields.io/badge/PowerShell-5.1-5391FE)
![Windows](https://img.shields.io/badge/Windows-10%20%7C%2011-0078D6)
![Read-only](https://img.shields.io/badge/mode-read--only-success)

DriverCheck — учебный CLI-инструмент, который показывает устройства, состояние драйверов и проблемы, **не изменяя систему**. Без установки драйверов, без записи в реестр и без сетевых запросов.

**Текущая версия:** `0.7.0` — этапы 1–3 завершены; проверка обновлений спроектирована, но ещё не реализована.

## Возможности

- `scan` — проверка устройств на ошибки и неполные данные о драйверах.
- `list` — подключённые сейчас устройства и установленные драйверы.
- `info` — сведения о системе и сводка по инвентарю.
- `help` — справка и коды возврата.
- Единая модель данных `Get-DcInventory` для всех команд.
- Разделение состояния устройства (`Status`) и наличия записи о драйвере (`DataQuality`).
- Понятные коды возврата для использования в скриптах.
- Совместимость с Windows PowerShell 5.1, без внешних модулей.

## Быстрый старт

```powershell
git clone https://github.com/JDela2003/drivercheck.git
cd drivercheck
.\drivercheck.ps1 scan
```

Если политика выполнения запрещает запуск локального скрипта, разрешите его только для текущего процесса:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\drivercheck.ps1 scan
```

## Команды

| Команда | Что делает |
|---|---|
| `help` | Показывает справку и коды возврата |
| `list` | Устройства, которые подключены сейчас, и их драйверы |
| `scan` | Проверяет устройства на ошибки, отдельно показывает неполные данные |
| `info` | Сведения о системе и сводка по инвентарю |

Пример `scan`:

```text

Работают без ошибок (код 0): 148
Не подключены сейчас (код 45): 37 — это не ошибка
Отключены пользователем (код 22): 0
Требуют внимания: 0
Состояние неизвестно: 0
Устройств с ошибками драйверов не найдено.
Неполные данные о драйвере: 38 — это не ошибка устройства
  из них присутствуют (Present): 1
  из них не подключены (NotPresent): 37
Конфликтующие записи о драйвере: 0
```

## Коды возврата

| Код | Значение |
|---|---|
| `0` | Успешно; для `scan` — проблем не найдено |
| `1` | `scan` нашёл устройства, требующие внимания |
| `2` | Неизвестная команда |
| `3` | Не удалось получить данные об устройствах |

Коды `NotPresent`, `Disabled`, `Partial` и `Conflict` не считаются проблемой устройства и не меняют код на `1`.

## Как это работает

`Get-DcInventory` читает два источника:

- `Get-PnpDevice` — класс, имя, `InstanceId`, `Present`, `ConfigManagerErrorCode`, `Status`;
- `Win32_PnPSignedDriver` — `DriverVersion`, `DriverDate`, `InfName`, `Manufacturer`, `IsSigned`, `Signer`.

Записи сопоставляются по `InstanceId`/`DeviceID` без учёта регистра. Статус устройства выводится из `ConfigManagerErrorCode`:

| Код | Статус | Смысл |
|---|---|---|
| `0` | `OK` | Устройство работает нормально |
| `45` | `NotPresent` | Устройство не подключено, это не ошибка |
| `22` | `Disabled` | Устройство отключено пользователем |
| другой | `Problem` | Проблема устройства |
| отсутствует | `Unknown` | Состояние неизвестно |

`Presence` хранится отдельно от `Status`: отсутствие кода не превращается в догадку.

`DataQuality`:

- `Ok` — есть одна полная запись о драйвере;
- `Partial` — записи нет или в ней не хватает `DriverVersion`/`InfName`;
- `Conflict` — несколько записей о драйвере.

`Partial` не является ошибкой устройства. У устройств с кодом 45 записи о драйвере обычно нет, потому что устройство не подключено; такие записи не попадают в «Требуют внимания».

## Безопасность

- Только чтение: программа не устанавливает, не удаляет и не изменяет драйверы.
- Нет записи в реестр, Driver Store и настройки системы.
- Нет сетевых запросов из `scan`, `list`, `info` и `help`.
- Нет обращения к серверам и файлам Driver Booster.
- Нет обхода лицензий и копирования закрытого кода.

## Ограничения

- Проверка обновлений пока не реализована: нужен надёжный источник сравнения. Проект описан в [`docs/UPDATE-CHECK.md`](docs/UPDATE-CHECK.md).
- Инструмент не называет драйвер «устаревшим» по дате или версии без проверяемых данных.
- Нет автоматических тестов; проверка изменений выполняется вручную (BOM, синтаксис, дифф, запуск команд пользователем).
- Проверено на Windows 11 Pro (build 26200) и Windows PowerShell 5.1.

## О проекте

DriverCheck вырос из учебного исследования: сначала — статический анализ коммерческого драйвер-апдейтера, затем — собственная read-only реализация на PowerShell и Windows API. Чужие бинарники, данные и закрытый код в проект не включены; используются только документированные интерфейсы Windows.
