# DriverCheck: проверка доступности обновлений драйверов

**Статус:** проект, код не реализован.
**Дата:** 2026-10-27.
**Связанные файлы:** `drivercheck.ps1` (v0.7.0), `research/driver_booster/REPORT.md` (раздел 14).

Документ описывает будущую команду проверки обновлений. Он не меняет `drivercheck.ps1` и не выполняет сетевых запросов.

---

## 1. Задача

Ответить на вопрос: **предлагает ли надёжный источник обновление драйвера для присутствующего устройства?**

Ответ должен быть честным:

- «обновление предлагается» — только если источник вернул обновление, совпавшее с устройством;
- «обновление не предлагается» — не значит «драйвер самый новый»;
- «неизвестно» — если данных для вывода недостаточно.

Текущая команда `scan` отвечает на другой вопрос: «есть ли у устройства ошибка». Эти слои нельзя смешивать.

## 2. Границы

В этой фазе запрещено:

- скачивать, устанавливать, удалять и заменять драйверы;
- менять реестр, Driver Store и настройки системы;
- обращаться к серверам Driver Booster и использовать его файлы;
- копировать закрытый код и лицензионную логику Driver Booster;
- автоматически ходить в сеть из `scan`, `list`, `info` и `help`;
- объявлять драйвер «устаревшим» только по дате или версии без проверяемого источника.

Разрешено: читать метаданные устройств и выполнять поиск обновлений **только по явной команде** и **только после отдельного согласования** сетевого шага.

## 3. Что уже есть

`Get-DcInventory` объединяет:

- `Get-PnpDevice` — класс, имя, `InstanceId`, `Present`, `ConfigManagerErrorCode`, `Status`;
- `Win32_PnPSignedDriver` — `DriverVersion`, `DriverDate`, `InfName`, `Manufacturer`, `IsSigned`, `Signer`.

Этого достаточно для диагностики устройства, но **недостаточно** для проверки обновлений: нет `HardwareID`/`CompatibleID`, по которым обновление сопоставляется с устройством.

## 4. Источник: Windows Update Agent

### 4.1 Что это

Встроенный в Windows COM-интерфейс `Microsoft.Update.Session`. Позволяет искать обновления, включая драйверы, без скачивания и установки.

### 4.2 Что подтверждено документацией Microsoft

Интерфейс `IWindowsDriverUpdate` содержит свойства:

| Свойство | Смысл |
|---|---|
| `DriverClass` | класс драйвера |
| `DriverHardwareID` | Hardware ID или Compatible ID, которому должно соответствовать обновление |
| `DriverManufacturer` | производитель |
| `DriverModel` | модель устройства |
| `DriverProvider` | поставщик драйвера |
| `DriverVerDate` | дата версии драйвера |
| `DeviceProblemNumber` | код проблемы устройства, с которым связано обновление |
| `DeviceStatus` | статус этого устройства |

Источник: Microsoft Learn, [`IWindowsDriverUpdate Properties`](https://learn.microsoft.com/en-us/windows/win32/wua_sdk/iwindowsdriverupdate-properties) (страница обновлена в 2025 году).

### 4.3 Чего источник не даёт

В документации **нет структурированного свойства с версией драйвера кандидата**. Есть только дата (`DriverVerDate`).

Версия иногда встречается в тексте заголовка обновления (`Title`), но формат заголовка зависит от производителя и языка. Разбор заголовка — догадка, а не надёжное сравнение.

**Вывод:** на первом этапе WUA может честно ответить «Windows Update предлагает обновление для этого Hardware ID», но не «версия кандидата новее установленной».

## 5. Сопоставление устройства и обновления

1. Для присутствующих устройств получить `HardwareIds` и `CompatibleIds` (например, через `Get-PnpDeviceProperty` и ключи `DEVPKEY_Device_HardwareIds` / `DEVPKEY_Device_CompatibleIds`; точный источник подтвердить).
2. Для каждого обновления взять `DriverHardwareID`.
3. Сравнивать строки без учёта регистра, точным совпадением. Никаких «похожих» имён и догадок.
4. Если совпадений несколько — показать все, не выбирать молча.
5. Устройства с `Presence = NotPresent` не проверять: для них нет кандидата, это `NotApplicable`, а не «нет обновлений».

## 6. Версии и даты

- Установленная версия: `Win32_PnPSignedDriver.DriverVersion` (строка).
- Версия кандидата: **неизвестна**, пока не найден надёжный структурированный источник.
- Дата кандидата: `DriverVerDate` — только справочная информация. Дата не доказывает, что версия новее.
- Сравнение версий — только числовое (компоненты через точку), не строковое. Пример ошибки: строка `"9.0.9.9"` лексикографически больше `"10.0.1.2"`, хотя численно меньше.
- Если формат версии не распознан — `Unknown`, а не «старее».

## 7. Вердикты

| Вердикт | Когда | Что означает |
|---|---|---|
| `Offered` | источник вернул обновление, совпавшее по Hardware ID | Windows Update предлагает драйвер для устройства |
| `NotOffered` | совпадений нет | источник ничего не предложил; это **не** доказательство актуальности |
| `Unknown` | нет данных, несколько неоднозначных кандидатов, ошибка источника | вывод невозможен |
| `NotApplicable` | устройство не подключено или у него нет драйвера | проверка не имеет смысла |

Слова «устарел» (`Outdated`) в выводе нет: для него нужны обе версии и правило сравнения, которых пока нет.

## 8. Формат вывода (проект)

```text
Class        FriendlyName              InstalledVersion  CandidateDate  Verdict     Match
-----        ------------              ----------------  -------------  -------     -----
Display      Intel(R) UHD Graphics      27.20.100.9316    2024-05-12     Offered     PCI\VEN_8086&DEV_9BC4
Net          Intel(R) Wi-Fi 6 AX201     22.40.0.7         —              NotOffered  —
```

Дополнительно:

- `Источник: Windows Update Agent`;
- `Время проверки`;
- `Режим: только поиск, без скачивания и установки`;
- предупреждение, если поиск неполный.

## 9. Коды возврата (предложение)

| Код | Значение |
|---|---|
| `0` | проверка выполнена, обновлений не предложено |
| `1` | есть хотя бы одно предложенное обновление |
| `3` | источник недоступен или поиск не выполнен |
| `4` | результат неполный: часть устройств осталась `Unknown` |

Коды `1` и `3` используют ту же схему, что и `scan`, но здесь `1` означает «есть предложенные обновления», а не «есть проблемы с устройством». Итоговое решение нужно принять до реализации.

Приоритет кодов при смешанном результате: `3` → `4` → `1` → `0`.

## 10. Сеть и приватность

- Сеть — только в отдельной команде (рабочее имя `check-updates`), только по явному запуску.
- `scan`, `list`, `info`, `help` в сеть не ходят.
- Разрешён только поиск (`Search`). Скачивание (`Download`) и установка (`Install`) запрещены.
- Таймаут и понятное сообщение при отсутствии сети.
- WUA сам обращается к серверам Microsoft; DriverCheck не добавляет своей телеметрии и не отправляет инвентарь третьим лицам.
- Поиск может зависеть от политики Windows Update и состояния службы; это нужно проверить.

## 11. Ошибки и ограничения

- Windows Update отключён политикой или служба недоступна → `3`.
- Нет сети → `3`.
- Обновление не предлагается → `NotOffered`, но не «актуально».
- OEM-драйверы могут отсутствовать в Windows Update.
- Несколько обновлений на одно устройство → показать все.
- Обновление может быть скрытым или необязательным; это часть политики WUA, а не решение DriverCheck.
- Дата драйвера не заменяет версию.

## 12. План проверки (read-only, требует разрешения)

1. Создать объект `Microsoft.Update.Session` **без поиска** — проверить, что COM доступен.
2. Выполнить поиск драйверов:
   `IsInstalled=0 and Type='Driver'` (точный синтаксис подтвердить).
3. Вывести количество найденных обновлений и заполненность полей `DriverClass`, `DriverHardwareID`, `DriverVerDate`, `Title`.
4. Сопоставить `DriverHardwareID` с `HardwareIds` присутствующих устройств.
5. Проверить работу без прав администратора.
6. Отдельно проверить поведение при отсутствии сети (не отключая сеть принудительно).

**Важно:** шаг 2 делает сетевой запрос к Windows Update. Он выполняется только после явного согласия пользователя.

## 13. Открытые вопросы

- Содержит ли `DriverHardwareID` одно значение или список?
- Заполняется ли `DriverVerDate` у всех драйверных обновлений?
- Можно ли надёжно получить версию кандидата без разбора `Title`?
- Появляются ли OEM-драйверы (Lenovo/Intel) в результатах на этой машине?
- Требуются ли права администратора для поиска?
- Как ведёт себя поиск при отключённой службе Windows Update?

## 14. Решение по умолчанию

Первая реализация — **только `Offered` / `NotOffered` / `Unknown`**, без сравнения версий и без слова «устарел». Это честно отражает то, что реально известно из WUA.

Сравнение версий добавляется только после того, как найден структурированный и проверяемый источник версии кандидата. Разбор заголовка допускается лишь как помеченный `inferred`-вариант и не должен менять вердикт `Offered` на «устарел».

## 15. Что не делаем в этой фазе

- не добавляем команду в `drivercheck.ps1`;
- не ходим в сеть;
- не меняем `Get-DcInventory`;
- не трогаем `list`, `scan`, `info`, `help`;
- не используем Driver Booster и его данные.
